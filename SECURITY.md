# Security Policy

Thank you for helping keep TMW-RP secure and respectable.

If you discover a security issue, please report it as a bug through the normal project issue flow and be clear that this is a responsible disclosure. We appreciate thoughtful, precise reporting and we value reports that include a reproduction path, affected behavior, and a proposed fix or mitigation when possible.

## Responsible disclosure process

Please:

- report the issue as a bug with the clearest reproduction steps available
- describe the impact, scope, and likely severity
- include any proof of concept or minimal conditions required to trigger the issue
- propose a practical fix or mitigation when possible
- be respectful of the fact that this project is intentionally browser-native and public-source-first

We prefer to solve issues in a way that is safe, understandable, and works out of the box whenever possible. If a vulnerability is serious, we ask that you do not rely on a vague explanation alone; try to include a path to a real, practical solution.

## Reporting channel

For serious issues, contact:

- contact@mitsuolabs.com

Please include a concise subject line and enough technical detail for triage.

## Scope

This project is a browser-only public radio client. Security concerns may involve:

- unsafe stream handling
- malicious or hostile URL injection
- browser execution problems
- metadata abuse or shell exploitation through browser behavior
- release, governance, or automation tampering

We do not treat all browser quirks as vulnerabilities if they are ordinary runtime constraints of public web content. We do treat deliberate abuse, malicious exploitation, and unsafe data flow as security issues.

## Expected response

We aim to review and respond to responsibly disclosed issues in a timely and practical way. Where a fix is feasible, we prefer to ship it directly and document the mitigation clearly.

Thank you for helping keep the project secure, public, and responsibly built.
